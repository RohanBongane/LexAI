MODULE 1: DATABASE AND MYSQL MASTERY

A. MySQL Fundamentals

  • Database: An organized collection of data. In LexAI, we use a relational database where data is stored in tables (like Excel spreadsheets) connected by relationships.
  • Primary Key (PK): A unique ID for every record (e.g., user.id = 1).
  • Foreign Key (FK): A column that links to another table's Primary Key. For example, document.user_id links to user.id, proving who owns the document.

B. Actual Database Schema (ER Diagram Logic)

LexAI uses 6 core tables defined in models/database_models.py: 1. Users: id (PK), name, email (Unique), password_hash, role. 2. Documents: id (PK), user_id (FK -> Users), filename, file_type, status, extracted_text. (One-to-Many: 1 User has Many Documents). 3. DocumentAnalysis: id (PK), document_id (FK -> Documents), summary (JSON), risks (JSON). (One-to-One: 1 Document has 1 Analysis). 4. Conversations: id (PK), user_id (FK), document_id (FK). Tracks chat sessions. 5. Messages: id (PK), conversation_id (FK -> Conversations), sender (user/ai), message. 6. KnowledgeBase: id (PK), title, content, category. (Curated by Admins).

C. SQLAlchemy Explained

LexAI uses Flask-SQLAlchemy (an ORM - Object Relational Mapper). Instead of writing raw SQL strings, you write Python classes. * Code Excerpt: new_doc = Document(user_id=user_id, filename=safe_filename) * Saving to DB: db.session.add(new_doc) followed by db.session.commit(). * Analogy: The ORM is an automatic translator. You speak Python, and it translates your commands into SQL for MySQL to understand.

D. SQL Practical Lab (Safe Queries)

To manually inspect your MySQL database via command line: * SHOW TABLES; -> Lists all tables. * DESCRIBE users; -> Shows the columns in the Users table. * SELECT email, role FROM users; -> Fetches all user emails. * (Hypothetical Update): UPDATE users SET role='admin' WHERE id=1;

MODULE 2: AI, GEMINI API, CHROMADB AND RAG

A. Gemini API Integration

LexAI uses the official google-genai SDK. * Initialization: client = genai.Client(api_key=api_key) is called in rag_service.py. * Model: Uses gemini-3.6-flash (or the model specified in AI_MODEL config). * Handling Errors: Wrapped in a try/except block. If Gemini throws a 429 Quota Exceeded error, LexAI triggers construct_fallback_response() to serve raw Knowledge Base data without crashing.

B. Document Processing & Chunking

Found in document_service.py: 1. Extraction: PyMuPDF is used for PDFs; python-docx is used for Word files. 2. Chunking (embedding_service.py): The extracted text is split into chunks of 1000 words with an overlap of 150 words to ensure sentences aren't cut in half.

C. Embeddings

Found in embedding_service.py: * Model: LexAI uses the local SentenceTransformer('all-MiniLM-L6-v2'). * Concept: It converts text into an array of 384 numbers. Similar texts end up mathematically close to each other in vector space.

D. ChromaDB

ChromaDB is a local vector database running from the chroma_db folder. * Collection Name: lexai_documents. * Metadata: Every chunk is saved with metadata like {"user_id": 1, "document_id": "uuid"}. This ensures User A's searches never return User B's documents.

E. RAG in LexAI (Step-by-Step)

  1. User types "What are my termination risks?"
  2. classify_intent determines if it's Document-Specific or General Legal.
  3. embed_question() converts the question into numbers.
  4. ChromaDB searches lexai_documents and retrieves the 8 mathematically closest chunks, strictly filtering by user_id.
  5. These 8 chunks are injected into a massive strict prompt (prompt = f"""You are LexAI... RETRIEVED CONTEXT: {context_text}""").
  6. Gemini reads the context and generates an answer strictly based on the provided text.

MODULE 3: COMPLETE PROJECT WORKFLOW

Workflow D: Document-Specific Chat (Trace)

  1. Frontend: User clicks "Send" in chatbot.html.
  2. JS Fetch: chatbot.js sends a POST request with JSON payload {"message": "hi", "document_id": "123"}.
  3. Flask Route: chat_routes.py @chat_bp.route('/api/chat') receives it.
  4. Service Call: Calls answer_question(user_id, question, document_id) in rag_service.py.
  5. ChromaDB: Filters vectors where document_id == 123 and user_id == current_user.id.
  6. Gemini: Generates response.
  7. Database: Route saves the exchange to the Messages table.
  8. Frontend: JS receives JSON, renders Markdown using marked.js, and displays it.
